# Digital Nomad Job Dashboard

여러 공개 구인 피드와 직접 추가한 공고를 한 화면에서 검색·필터·정렬하는 개인용 대시보드입니다.

웹 서비스: https://ostrichick.github.io/job-search-radar/

## 실행

가장 간단한 방법은 `Start-Job-Dashboard.cmd`를 더블클릭하는 것입니다. 서버 창을 닫으면 대시보드도 종료됩니다.

터미널에서는 다음과 같이 실행할 수 있습니다.

```powershell
cd C:\projects\DigitalNomad\job-dashboard
npm run refresh
npm start
```

브라우저에서 `http://127.0.0.1:4317`을 엽니다.

`local-server.mjs`는 데스크톱 바로가기용 로컬 서버이며 웹 배포에는 사용하지 않습니다. 현재 GitHub Pages는 Actions가 `public/` 정적 UI와 최신 `jobs.json`을 생성해 배포하고, `api/`는 Vercel 보조 배포에서만 사용합니다.

서버가 켜져 있는 동안 6시간마다 자동 갱신하며, 마지막 수집이 6시간 이상 지난 상태에서 서버를 시작해도 자동으로 다시 수집합니다. 화면의 **목록 새로고침** 버튼으로 현재 피드를 다시 읽을 수 있습니다.

## 현재 자동 수집 소스

- Welo Global/Welocalize 공식 Lever 채용 API — 사용자 관심 분야와 한국/Worldwide/확인 필요 범위만 선별
- RWS TrainAI 공식 Lever 채용 API — 사용자 관심 분야와 한국/Worldwide/확인 필요 범위만 선별
- LILT 공식 Ashby 채용 API — 한국 대상 공개 공고 중 AI 평가·언어·데이터 관련 역할을 수집하고, 전문직 5년+ 등 미검증 하드요건은 추천에서 제외
- Meridial 공식 Greenhouse 채용 API — 한국어 AI 트레이너·언어 데이터 공고를 수집하고 코딩·전문 음성·STEM·기기 등 미검증 하드요건은 추천에서 제외
- OneForma 공식 WordPress REST 프로젝트 API — 한국어·South Korea·AI/언어/오디오 프로젝트를 관심 조건에 맞춰 선별
- We Work Remotely 공개 RSS — 현재 관심 조건과 맞는 공고가 있을 때만 포함
- Jobicy 공개 Remote Jobs API
- Remote OK 공개 JSON API
- Remotive 공개 Remote Jobs API
- Arbeitnow 공개 Job Board API
- 알바몬 공개 전북 지역 목록 + 상세 JobPosting 구조화 데이터 — 상세 근무지로 전주·완주를 최종 확인
- 알바천국 공개 검색 + 상세 JobPosting 구조화 데이터 — 상세 근무지로 전주·완주를 최종 확인
- 잡코리아 공개 검색 + 상세 JobPosting/모집요강 — 상세 근무지로 전주·완주를 최종 확인
- 사람인 공개 전주·완주 지역 목록 + 상세 페이지 — 상세 근무지 위치를 확인할 수 없는 공고는 제외
- 인크루트 공개 전주·완주 검색 + EUC-KR 상세 JobPosting — 검색 지역과 상세 posting ID/canonical URL/실제 주소가 같은 전주·완주 공고만 포함
- 고용24 공식 채용정보 OPEN-API — `WORK24_AUTH_KEY`가 구성된 경우에만 전주·완주 수집 활성화
- `data/manual-jobs.json`에 직접 추가한 공고

LinkedIn과 Indeed는 직접 크롤링하지 않습니다. 두 플랫폼에서 발견한 공고는 화면의 **공고 추가**로 저장할 수 있습니다. Gmail Job Alert 자동 유입은 Gmail OAuth 토큰을 정적 웹앱에 넣지 않는 구조가 전제이며, 별도 서버/Apps Script 등 안전한 OAuth 보관 경로가 생길 때 연결합니다.

자동 수집이 막혀 있거나 의도적으로 비활성인 플랫폼과 공식 알림/API를 이용한 대체 경로는 [`SOURCE_GAPS.md`](./SOURCE_GAPS.md)에 정리합니다. “접근이 어렵다”는 이유만으로 로그인·CAPTCHA·Cloudflare 우회 수집을 추가하지 않습니다.

잡플래닛 자동 수집은 현재 비활성입니다. 로그인·쿠키·브라우저 자동화·Cloudflare challenge 우회 없이 공개 검색 GET 200, 고유 Jobplanet posting ID, 개별 상세 페이지의 posting-specific 전주·완주 근무지 증거가 모두 확인될 때만 활성화합니다. 외부 잡코리아·사람인 공고로 연결되는 항목은 잡플래닛 출처로 다시 수집하지 않습니다.

회사 공식 ATS의 현재 공개 API에서 직접 확인된 공고만 `공식 ATS 모집 확인`으로 표시합니다. OneForma처럼 공식 프로젝트 플랫폼의 공개 페이지가 현재 게시된 경우는 `공식 프로젝트 게시 확인`으로 별도 표시하며, 페이지 게시가 실제 작업량·선발 가능성까지 보장한다는 뜻으로 사용하지 않습니다. 채용 보드/집계 피드는 `집계·채용보드 현재 피드`로 구분합니다. 45일이 지난 비공식 피드는 `오래된 공고`, 명시적인 talent pool/network 문구는 `인재풀·즉시 모집 아님`, 명시적인 모집 종료 문구·지난 마감일은 `종료 확인됨`으로 분류합니다. 상세 화면에는 이 판정의 이유, 마지막 확인 시각, 직접 확인한 공고 링크를 별도로 표시합니다.

Welo Global/Welocalize, RWS, LILT, Meridial, OneForma는 **공식 모집원 여부**와 **지급 신뢰 신호**를 별도 축으로 표시합니다. 공식 페이지에 실제 공고가 있다는 사실과 프리랜서 지급의 신뢰도는 같은 의미가 아닙니다. 지급 신호는 공식 지급 정책, 리뷰 집계, 커뮤니티 단일 사례를 구분하고 확인일·최근 출처일·반복성도 저장합니다. 단일 커뮤니티 후기는 보조 신호일 뿐 “검증됨”으로 취급하지 않으며, 긍정·부정 신호가 섞이면 `상반된 신호`, 공개 근거가 부족하면 `근거 부족`으로 표시합니다. LILT와 Meridial은 현재 공식 ATS 게시 여부는 직접 확인하지만 독립적인 최신 지급 근거가 부족하므로 지급 신뢰를 별도로 단정하지 않습니다.

지급 근거에는 freshness/expiry 정책이 있습니다. 기본적으로 공식 정책은 180일, 리뷰 집계는 120일, 단일 커뮤니티 사례는 90일을 재검토 주기로 사용합니다. 리뷰 집계는 “마지막으로 페이지를 확인한 날짜”가 아니라 집계 안의 **최근 출처 날짜**를 freshness 기준으로 삼습니다. 근거가 만료되면 과거의 주의 신호를 현재 사실처럼 계속 표시하지 않고 `근거 만료·재검토 필요` 또는 현재 남아 있는 근거 수준으로 자동 재분류합니다. 정책은 `config/payment-evidence-policy.json`에서 관리합니다.

각 공고는 새로고침 때 검증 결과를 단순 덮어쓰지 않습니다. 최초 발견, 원문 주요 필드 변경, 모집 상태 변경, 원천에서 사라짐, 재등장, 소스 확인 실패·복구, 지급 근거 freshness 변화와 7일 간격의 변경 없음 체크포인트를 `verificationHistory`에 최대 24개까지 보존합니다. `firstSeenAt / lastSeenAt / lastVerifiedAt / missingSince / missingCheckedAt / contentFingerprint`를 분리해 “마지막 성공 검증”과 “이번에 보이지 않음”을 혼동하지 않습니다. 카드에서는 최근 검증·원문 변경·재등장·근거 만료 임박·미확인 핵심요건만 짧게 표시하고 상세에서 최근 이력을 확인할 수 있습니다.

소스 품질도 공고 적합도와 별개로 누적 측정합니다. 최근 성공률, 연속 실패, 원천 후보 수, 프로필 일치 수, 최종 유지 수, 중복·저품질 비율, 공식성, coverage, 근거 갱신 가능성을 `sourceMetrics`에 최근 24회까지 보존합니다. **저수율 소스라는 이유만으로 개별 좋은 공고를 자동 제외하지 않으며**, 반복적인 수집 실패로 reliability가 `unstable/degraded`가 된 경우에만 기본 추천 기여를 중단합니다. 저수율은 UI의 소스 품질 참고 정보와 동점 정렬에만 반영됩니다.

중개 채용 보드가 제공하는 급여 메타데이터는 공고 본문보다 신뢰도가 낮을 수 있으므로 원문과 출처를 분리합니다. 본문에 급여가 있으면 본문을 우선하고, 메타데이터만 있는 경우에는 확정 급여처럼 표시하지 않습니다. 특정 미국 주에만 적용되는 급여 범위처럼 지역 한정 조건이 명시된 경우에도 해당 범위를 전 세계 지원자 단가로 일반화하지 않습니다.

상세 화면의 판단 근거는 다음 다섯 축을 섞지 않고 보여줍니다.

- **모집 확인** — 현재 공고인지, 어떤 규칙으로 판정했는지, 마지막 확인 시각과 직접 공고 링크
- **출처** — 공식 ATS/공식 프로젝트 플랫폼/채용 보드/집계 피드/직접 추가 중 어디서 수집했는지
- **지급 신뢰** — 공식 정책·리뷰 집계·단일 커뮤니티 사례의 종류, 최근성, 반복성, 상반 신호
- **지원 가능성** — 한국/Worldwide/특정 국가 제한/확인 필요 판정의 위치·거주 근거
- **검토 우선순위** — 일치 키워드와 관심 분야, 원격·지원 범위, 별도로 확인해야 할 경력·장비·거주 하드요건
- 카드에는 **지금 볼 이유 / 아직 미확인**을 짧게 요약하고, 상세에서 같은 근거를 확장해 확인할 수 있습니다.

## 웹 배포

- Vercel: `api/`의 서버리스 수집 API를 사용할 수 있는 보조 배포 구성이 남아 있습니다.
- GitHub Pages가 현재 영구 서비스입니다. `.github/workflows/pages.yml`이 6시간마다 또는 `main` push/수동 실행 시 Node 24에서 테스트 → 최신 피드 생성 → 피드 검증 → 이전 피드 기준선 저장 → Pages artifact 배포를 수행합니다.
- 배포 전에 단위 테스트와 영구 Playwright E2E를 모두 실행합니다. E2E는 결정론적 피드 fixture를 사용해 상태·필터·숨김 Undo·archived snapshot·상세 탐색·390px 레이아웃·빈/오류 복구·백업/가져오기뿐 아니라 검증 이력, 원문 변경, 사라짐→재등장, 부분 소스 실패→복구, 근거 expiry 재계산, 추천 세트 과도 축소를 회귀 방지합니다.
- Pages 설정은 GitHub Actions(`build_type=workflow`) 방식입니다. 서버 측 실행이므로 개인 PC가 꺼져 있어도 갱신됩니다.
- `docs/`는 Pages 배포 원본이 아니며 **`docs/jobs.json` 하나만** 마지막 검증 피드의 영속 기준선으로 유지합니다. Actions는 새 `public/jobs.json` 검증 후 이를 자동 커밋해 다음 6시간 실행이 직전 피드에서 이어지도록 합니다. 그래서 stable ID 승계, 출처 장애 fallback, 14일 실종 공고 grace의 `missingSince`가 PC 없이도 연속성을 유지합니다. UI는 `public/`에만 한 벌 유지합니다.
- `scripts/publish-pages.ps1`과 Windows 작업 스케줄러 `JobSearchRadarRefresh`는 롤백용으로 남겨 두었으며 현재 작업은 **비활성화**되어 있습니다. Actions 장애가 확인될 때만 다시 켭니다.
- 관심 공고, 지원 상태, 숨김, 직접 추가 공고와 필터 설정은 사용자의 브라우저 `localStorage`에 저장됩니다.
- 헤더의 **상태 백업 / 상태 가져오기**로 이 브라우저 상태를 버전이 있는 JSON 파일로 내보내고 다른 브라우저에 병합할 수 있습니다.
- LinkedIn 공식 Job Alert 이메일을 `npm run parse:linkedin-alert -- <내보낸-json>`으로 파싱한 결과 JSON도 **상태/알림 가져오기**에서 바로 병합할 수 있습니다. LinkedIn job ID를 안정 ID로 사용하므로 같은 알림을 다시 가져와도 중복되지 않습니다.
- 관심·지원 예정·지원함으로 관리하는 공고는 간단한 로컬 스냅샷도 함께 보관해, 이후 원천 피드에서 사라져도 해당 상태 화면에서 제목·회사·원문 링크를 계속 확인할 수 있습니다.

## 기능

- 현재 필터의 수집 공고를 기준으로 최근 7일 신규 공고, 직전 7일 대비 변화, 보수 금액 공개율, 공고 수 상위 분야, 추천 기준을 충족한 공고가 가장 많은 회사, 가장 많이 남은 확인 필요 항목을 보여주는 **시장 한눈에 보기**. 전체 채용시장 통계가 아니라 현재 수집 범위의 스냅샷임을 화면에 명시
- 추천 기본 필터로 일부 공고가 가려져 있어도 `현재 조건 / 숨김 제외 활성 전체` 규모를 함께 보여주고 **숨김 제외 활성 공고 보기**로 개인적으로 숨긴 공고를 다시 노출하지 않으면서 전체 후보 범위를 빠르게 확인
- 직무·회사·설명·태그 통합 검색
- 출처, 분야, 원격, `한국에서 지원 가능 / 전 세계 지원 가능 / 특정 국가 제한 / 확인 필요` 필터
- `모집 확인됨 / 현재 피드 / 오래된 공고 / 인재풀 / 종료 확인` 상태 필터
- 수집 출처 오류 시 이전 공고를 `출처 확인 실패`로 보존하고, 추적 중인 공고가 피드에서 사라지면 `현재 피드에서 사라짐`으로 표시
- 고용24 미설정, LinkedIn·Indeed 반자동 입력, 잡플래닛 공개 접근 제한처럼 **자동 수집 범위 밖인 출처와 현재 가능한 대체 경로**를 시장별 접이식 안내로 표시해 시장 요약의 사각지대를 함께 확인
- 정상 수집 중 원천 피드에서 사라진 공고도 14일 동안 `현재 피드에서 사라짐` 상태로 보존한 뒤 자동 정리해, 관심·지원 상태를 다른 안정 ID로 옮기거나 백업할 시간을 확보
- 최근 검증됨 / 원문 변경됨 / 재등장 / 출처 복구 / 근거 만료 임박 / 미확인 핵심조건 상태를 카드에서 빠르게 구분하고 상세에서 검증 이력 확인
- 출처별 최근 성공률·유효 공고 비율·저품질 비율·공식성·coverage·근거 갱신 가능성을 누적 추적하고 이상 상태만 상단 출처 건강 배너에 표시
- `공식 채용 페이지 확인 / 공식 프로젝트 게시 확인 / 집계·채용보드 현재 피드` 모집 상태 필터
- `공식 직접 채용 / 공식 프로젝트 플랫폼 / 채용 보드 / 집계 피드` 출처 검증 필터
- `반복 주의 신호 / 상반된 신호 / 단일 사례 / 공식 정책만 확인 / 근거 만료 / 근거 부족 / 지급 주체 아님` 지급 신뢰 근거 필터
- `추가 필수조건 감지 없음 / 일반 조건 확인 필요 / 필수조건 확인 필요` 필수조건 필터
- 검토 우선순위 임계값 필터
- 검토 우선순위·게시일·회사·직무명 정렬
- 기본 추천 조건까지 포함한 현재 적용 조건을 칩으로 보여주고, 조건별 해제 또는 `조건 모두 해제`로 전체 활성 공고 범위를 바로 확인
- 새 공고/내용 미확인/관심/지원 예정/지원함/숨김 흐름과 숨김 복구. 상세·원문을 열거나 사용자가 명시적으로 `내용 확인함` 처리한 경우에만 확인 상태로 기록하며, 관심·지원 상태·숨김 변경만으로는 확인 처리하지 않음
- 여러 공고 선택 후 관심·지원 예정·지원함·내용 확인함·숨김 일괄 처리
- 상세 보기 이전/다음 탐색
- 회사·제목·지역 범위를 고려한 중복 공고 통합과 다른 출처 링크 보존
- 통화·범위·주기를 구조화한 급여 표시. 원천 정보가 불완전하면 `확인 필요`로 표시
- 필터·검색 상태 유지, 60개 단위 더 보기, 빈 결과 초기화, 로드 오류 재시도
- 모바일에서는 검색·소스·지원 범위·내 상태를 우선 노출하고 나머지 필터를 접을 수 있는 `추가 필터`로 정리
- 사용자의 관심 직무 키워드와 검증 가능한 요건에 따른 기본 검토 우선순위 점수

검토 우선순위 점수는 채용 가능성 예측이 아닙니다. 추천 정책 v3부터는 한국에서 근무할 수 있거나 가까운 공고라는 이유만으로 `추천 공고`가 되지 않으며, 직무명·업무 설명에 사용자의 관심 업무와 직접 일치하는 근거가 있어야 합니다. 위치 조건만 맞는 일반 지역 공고는 삭제하지 않고 `시장 탐색 후보`로 남겨 전체 지역 시장을 볼 때 확인할 수 있습니다. 검증된 AI 평가·데이터 어노테이션·품질 검토·루브릭 QA 경험은 해당 경험을 직접 요구하는 AI 데이터 역할에 반영합니다. 반대로 컴퓨터과학 학위를 전문 개발 경력으로 보거나 한국어 교육 경력을 전문 번역·카피라이팅·접근성·법률·의학 경력으로 간주하지 않습니다. 검증되지 않은 전문 도메인·장기 거주·기기·언어수준·필수 실무경력 요건에는 경고를 붙이고 기본 추천 우선순위를 낮춥니다. `config/search-profile.json`에서 키워드와 검증된 capability 태그를 관리합니다.

## 검증

```powershell
npm run check
npm run test:e2e
npm run build:static
node scripts/validate-feed.mjs public/jobs.json docs/jobs.json
```

`scripts/validate-feed.mjs`는 ID 중복뿐 아니라 모든 공고의 지원범위 판정 근거, 모집 상태 판정 강도, 소스 coverage, 지급 신뢰 freshness/expiry, 필수요건 상태, content fingerprint, 검증 이력, sourceMetrics 지속성을 확인합니다. 공식 ATS 또는 공식 프로젝트 게시로 표시하는 공고는 마지막 확인 시각과 해당 공고의 직접 링크가 반드시 있어야 합니다. 비공식·집계 소스의 10점 미만 noise는 피드에 남지 않습니다. 같은 `recommendationPolicyVersion` 안에서는 직전 검증 피드와 비교해 설명되지 않는 추천 세트 급감을 차단하고, 의도적인 추천 정책 변경은 버전을 올려 명시적으로 재기준화합니다. OneForma는 한국어 taxonomy를 우선 사용하되, South Korea가 명시되고 본문이 “해당 위치의 언어 native/fluent”를 직접 요구하는 프로젝트는 taxonomy 누락으로 버리지 않고 포함한 뒤 거주·경력 하드요건으로 추천 여부를 별도 판정합니다.
